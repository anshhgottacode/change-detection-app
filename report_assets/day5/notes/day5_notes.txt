2. UI structure (as coded)
--------------------------
- Stack: React + Vite + Tailwind CSS, lucide icons, Inter font; talks to the FastAPI backend through VITE_API_URL.
- Layout: sticky header with an API status dot (online / offline / checking); a left settings panel and a results area; on narrow screens the panel stacks above the results.
- Image inputs: Before and After drop zones with browse, preview, remove button; JPEG, PNG and WebP only; size limit taken from the server's /config (10 MB by default).
- Method: Difference or SSIM.
- Preparation: "Align images" switch; lighting correction Off, CLAHE or Match.
- Sensitivity: "Automatic threshold" switch (Otsu) and a manual Threshold slider (0-255; disabled while automatic).
- Advanced (collapsible): blur (1-21, odd steps), minimum region area (0-2000 px), processing width (640, 960, 1280).
- Result views: Overlay, Mask, Heatmap, Compare (before/after slider); an Alignment tab (blend before/after alignment slider and matched points) appears only when alignment succeeded.
- Cards: Changed (% of all pixels, or of the overlapping area when aligned), Regions, Threshold, Time.
- Banners: green when alignment succeeded (matching points and overlap %), amber when it failed (with the reason).
- States: empty instructions, loading skeleton (with a "taking longer than usual" note after 6 s), error box with "Try again", Cancel button during analysis.
- Not implemented yet: dark mode, sample images, downloads, history, animation polish.

5. Repeatability of alignment
-----------------------------
MEASURED:
- repeat_check.py (shiftstatic, diff, align, 10 repeated runs in one process): every run gave 4.595%, 17 regions, 186 inliers, 62.33% overlap. Distinct results: 1.
- Five repeated API calls (test_api.py shiftstatic --align): every call returned 4.595%, 17 regions, threshold 52, keypoints 2911 / 3000, 296 matches, 186 inliers, 62.33% overlap.

| 2 | 54.6 | 59.9 | 15.7 | 28.7 | 128.7 |
| 3 | 59.3 | 64.1 | 16.8 | 25.9 | 128.4 |
| 4 | 60.4 | 65.7 | 18.0 | 34.1 | 135.7 |
| 5 | 60.6 | 66.0 | 17.7 | 29.7 | 136.9 |

- Calls 2-5: align 54.6-60.6 ms, request 128.4-136.9 ms.
- Call 1 took about 1.9 s in the alignment stage. Day 3's first aligned run was also about 1.9 s (1878 ms).
INTERPRETATION: consistent with a one-time start-up cost on the first alignment call. Not verified. Do not report 1.9 s as typical.

The odd Day 4 run (one shiftstatic API run: 10.114%, 25 regions, threshold 46, 212 inliers, 68.32% overlap; align 905 ms, threshold 87 ms, encode 104 ms, request 1238 ms) was not reproduced in these 15 later repeats (10 in-process, 5 API). Its slow timings suggest the machine was busy, but that does not explain the different warp. The cause is unknown. In the paper, report that alignment gave identical results in 15 repeats and mention the single unexplained run; do not claim alignment is deterministic in all conditions.

8. Dark theme clarification (correction)
----------------------------------------
REPORTED: an extra dark theme was applied in the author's browser.
Consequence: the frontend as coded has a light theme (white cards, slate background, indigo accent). The earlier statement "dark-themed interface" was wrong. Every Day 5 screenshot shows the browser's forced dark rendering (for example the blue file names and lilac "browse" link are browser colour changes), not the app's own design. The app has no dark mode of its own yet.
