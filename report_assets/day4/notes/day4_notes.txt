Day 4 Notes — API, Tests, Benchmark, and Deployment
====================================================

API design
----------
Application:
- FastAPI title/version: Change Detection API, version 0.4.0.
- Endpoints: GET /, GET /health, GET /config, POST /analyze.
- GET /health response: {"status": "ok", "version": "0.4.0"}.
- GET /config exposes max_upload_mb, max_width_cap, supported methods, normalisation options, and defaults.
- Defaults: method=diff, blur=5, threshold=automatic/Otsu, morph_kernel=5, min_area=200,
  max_width=1280, align=false, normalize=none.

POST /analyze parameters:
- before, after: required uploaded image files.
- method: "diff" or "ssim".
- blur: integer 1–21; default 5.
- threshold: empty/auto for Otsu, or integer 0–255; default automatic.
- morph_kernel: integer 1–31; default 5.
- min_area: integer 0–1,000,000; default 200.
- max_width: integer 320–MAX_WIDTH_CAP; default 1280. MAX_WIDTH_CAP defaults to 1920.
- align: boolean; default false.
- normalize: "none", "clahe", or "match"; default "none".

Image validation and limits:
- Maximum upload size: 10 MB per image by default (MAX_UPLOAD_MB can override this).
- Maximum pixels: 40,000,000 per image by default (MAX_PIXELS can override this).
- Minimum image dimensions: 32 × 32 px (MIN_SIDE = 32).
- Accepted formats: JPEG, PNG, WebP.
- Processing width cap: 1920 px by default (MAX_WIDTH_CAP can override this).
- Error handling observed in tests: invalid image/empty/too-small image → HTTP 400; oversized image → HTTP 413;
  invalid parameter/missing required file → HTTP 422.
- The blur and morphology kernel ranges are validated by FastAPI. The pipeline may adjust an even blur
  kernel to an odd value internally.

Response fields:
- Top-level keys: stats, timing, settings, images.
- stats: change_percent, regions, threshold, width, height, aligned, alignment_note,
  keypoints_before, keypoints_after, matches, inliers, valid_percent.
- timing: preprocess_ms, align_ms, change_map_ms, threshold_ms, postprocess_ms,
  pipeline_ms, decode_ms, encode_ms, request_ms.
- settings: method, blur, threshold, morph_kernel, min_area, max_width, align, normalize.
- images: before, after, heatmap, mask, overlay; when alignment succeeds, also blend_raw,
  blend_aligned, matches. Images are returned as base64 data URIs.
- Limits can be changed through environment variables where configured.

Benchmark observations:
- diff without alignment was fastest: pipeline mean 1.3 ms at width 640 and 4.4 ms at width 1280.
- SSIM without alignment increased from 31.1 ms at width 640 to 120.8 ms at width 1280.
- Alignment adds substantial processing cost; SSIM plus alignment was the slowest configuration, with a pipeline
  mean of 196.1 ms at width 1280.
- Client time includes end-to-end client overhead and is higher than server request time.
- SSIM plus alignment at width 960 showed relatively high variability: pipeline 116.0 ± 21.2 ms,
  request 150.9 ± 29.3 ms, and client 175.1 ± 30.1 ms.
