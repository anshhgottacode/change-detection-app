Day 6 Notes — Ground Truth, Evaluation, UI Tests

Evidence convention

-   MEASURED: values supplied from the Day 6 evaluation table, sweep
    output, or Day 3 ablation CSV.
-   REPORTED: UI checks reported as passed and developer-verified.
-   INTERPRETATION: cautious reading of measured results.
-   Annotation protocol and dataset descriptions below reflect the
    annotator’s report.

Annotation protocol

Annotator/tool: Photopea. Time spent: approximately 5–10 minutes per
pair. Annotation approach: marked objects that were present/absent
between each pair. - Mark objects that were added or removed. Where an
object is clearly moved, mark the relevant old/new object positions as
represented in the pair. - Do not mark shadows, lighting differences,
reflections, or black borders outside the valid aligned overlap as
object changes. - Do not label an object as removed if it is merely
cropped out of the other image. - pair2 is a satellite pair and was
considered too uncertain to mask, so it was excluded from annotated
evaluation. - pair3 has an alignment difference and a missing object;
interpret its pixel metrics cautiously because alignment/cropping can
affect which regions are comparable. - Masks use white (255) for changed
pixels and black (0) for unchanged pixels; masks must match the
processed image dimensions.

Dataset

Annotated change pairs: - pair1 — desk/object scene. Objects
present/absent between the images were marked. Template dimensions
reported as 1280 × 720. Alignment succeeded in preparation output; valid
overlap 99.0%. - pair3 — desk scene with an alignment difference and a
missing object. Template dimensions reported as 1280 × 721. Alignment
succeeded in preparation output; valid overlap 76.0%. Alignment/cropping
means only comparable overlapping regions should be interpreted. -
shiftobj — desk scene with a white earbuds case, laptop, pencil and
plastic container. Intended change includes the earbuds case changing
position. Template dimensions reported as 1152 × 648. Alignment
succeeded; valid overlap 79.2%. - lightobj — desk/object scene with an
illumination/appearance difference. Template dimensions reported as 1280
× 720. Alignment succeeded; valid overlap 98.6%. Lighting differences,
shadows and reflections should not themselves be marked as object
changes.

Static/no-intended-change control pairs: - lightstatic — assumed
static/no intended change. Day 3 notes say one photo was taken with the
light on and the other with the light off. Auto-exposure status was not
verified. Dimensions in Day 3 ablation: 1152 × 648. - nochange — assumed
static/no intended change. Dimensions in Day 3 ablation: 648 × 1152. -
shiftstatic — assumed static/no intended change, with camera/view
displacement requiring alignment. Dimensions in Day 3 ablation: 1152 ×
648.

Satellite pair: - pair2 — satellite images, dimensions 1280 × 1570 in
Day 3 results. Excluded from annotated evaluation because changes were
too uncertain to mask. Do not report precision, recall, F1 or IoU for
this pair without a ground-truth mask.

Dataset caveat: - Static labels are an assumption that no intended scene
change occurred, not a manually annotated pixel-level mask. Their
reported “false-change” percentage is the predicted changed-pixel
percentage under this assumption.

Evaluation setup

Evaluation code details supplied from eval_utils.py: - STATIC =
{“nochange”, “shiftstatic”, “lightstatic”}. - Static pairs receive an
all-zero ground-truth mask. - Annotated pairs load
../ground_truth/_gt.png; missing ground truth causes the pair to be
skipped. - Ground-truth mask is converted to boolean using gt > 127. - A
dimension mismatch stops evaluation and asks for the mask to match the
processed before-image dimensions. - Common evaluation region (ROI):
valid overlap from detect_changes(before, after, method=“diff”,
align=True) if alignment succeeds; if alignment fails, the whole
processed frame is used. - Metrics: precision, recall, F1, IoU,
predicted changed-pixel percentage, and counts of TP/FP/FN/ROI pixels. -
For static controls, recall is n/a because the assumed ground truth
contains no positive pixels. F1 and IoU are recorded as 0.000 in the
supplied table; interpret these as the evaluation convention for static
controls, not evidence that a model detected no false positives.
Predicted changed-pixel percentage is the useful false-change measure.

Variants and default settings: - V1_diff: method=“diff”. - V2_ssim:
method=“ssim”. - V3_diff_align: method=“diff”, align=True. -
V4_diff_clahe: method=“diff”, normalize=“clahe”. - V5_diff_match:
method=“diff”, normalize=“match”. - V6_diff_align_clahe: method=“diff”,
align=True, normalize=“clahe”. - V7_diff_align_match: method=“diff”,
align=True, normalize=“match”. - V8_ssim_align: method=“ssim”,
align=True. - Project defaults recorded in earlier notes: blur=5,
threshold=automatic/Otsu, morph_kernel=5, min_area=200, max_width=1280,
align=False, normalize=“none”. Variant definitions above override
alignment, method or normalization where specified. - The main
comparison uses the fixed variant configurations above. A separate sweep
varies threshold, min_area and blur; the sweep values are reported
separately below and are not substituted into the fixed-configuration
table. - The sweep is a parameter-sensitivity exploration on the same
annotated pairs, so its best pair-specific values are not held-out test
scores.

Problems found and anything odd

-   pair2 satellite alignment repeatedly fails because 13 good matches
    are below the required minimum of 15.
-   nochange appears worse with V3 alignment: 0.68% predicted change for
    V1 versus 16.97% for V3 in Day 6; Day 3 values were 0.759% and
    17.044%.
-   Static-pair predictions can remain large after alignment:
    lightstatic V3 = 43.75%; shiftstatic V3 = 4.60%.
-   V2_ssim predicts 89.95% changed pixels on shiftstatic and 50.80% on
    pair3; SSIM is not uniformly robust across these scenes.
-   pair3 F1 is very low for all variants despite high recall for some
    unaligned variants; high recall alone does not imply a good mask
    when precision is extremely low.
-   Best F1 differs by pair: pair1 V2_ssim = 0.820; lightobj
    V8_ssim_align = 0.538; shiftobj V3_diff_align = 0.658; pair3
    V3_diff_align = 0.056.
-   Main comparison uses fixed variant configurations, while the
    separate sweep explicitly explores threshold/min_area/blur. Keep
    sweep maxima separate from fixed comparison to avoid presenting
    pair-specific tuning as untouched test performance.
-   pair3’s alignment difference and missing object should be considered
    when evaluating its unusually poor scores.
